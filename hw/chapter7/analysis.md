# Chapter 7 Assignment: CPU Scheduling

## Q1: 三个长度均为 200 的任务，SJF 与 FIFO
- Prediction / 预测:
三个任务同时到达，按顺序各跑 200 个时间单位。
响应时间：0、200、400，平均 200。
周转时间：200、400、600，平均 400。
等待时间：0、200、400，平均 200。
SJF 和 FIFO 结果相同。
- Reasoning / 理由:
任务长度相同，SJF 没有"更短的任务"可以提前，所以执行顺序和 FIFO 完全一样。每个任务的响应时间等于它前面所有任务的运行时间之和，周转时间等于响应时间加自己的长度。
- - Verified result / 验证结果:
FIFO 和 SJF 的结果完全相同：平均响应 200.00，平均周转 400.00，平均等待 200.00（见 data/q1_fifo.txt、data/q1_sjf.txt）。
- Analysis / 分析:
预测正确。三个任务长度相同，SJF 没有更短的任务可以提前，所以执行顺序和 FIFO 一样。

## Q2: 长度 100、200、300，SJF 与 FIFO
- Prediction / 预测:
执行顺序 100、200、300。
响应时间：0、100、300，平均 133.33。
周转时间：100、300、600，平均 333.33。
等待时间：0、100、300，平均 133.33。
SJF 和 FIFO 结果相同。
- Reasoning / 理由:
任务已经按从短到长排好，SJF 选择最短任务的顺序与 FIFO 的到达顺序一致，所以两者执行序列相同。
- - Verified result / 验证结果:
FIFO 和 SJF 的结果完全相同：平均响应 133.33，平均周转 333.33，平均等待 133.33（见 data/q2_fifo.txt、data/q2_sjf.txt）。
- Analysis / 分析:
预测正确。任务已经按 100、200、300 从短到长排列，SJF 选出的顺序和 FIFO 的到达顺序一致。

## Q3: RR（时间片 1）
- Prediction / 预测:
工作负载 200、200、200：响应时间 0、1、2，平均 1；周转时间 598、599、600，平均 599；等待时间 398、399、400，平均 399。
工作负载 100、200、300：响应时间 0、1、2，平均 1；周转时间 298、499、600，平均 465.67；等待时间 198、299、300，平均 265.67。
- Reasoning / 理由:
RR 每个任务轮流跑 1 个时间单位，所以三个任务依次在第 0、1、2 个 tick 第一次运行，响应时间很短。但每个任务都被拖到接近最后才完成。200、200、200 时，三个任务每轮占 3 个 tick，任务 0 的最后一个 tick 在第 598 个 tick 结束，任务 1、2 依次是 599、600。100、200、300 时，任务 A（100）在第 298 个 tick 完成；之后只剩两个任务交替，B（200）在第 499 个 tick 完成，C（300）最后独自运行，在第 600 个 tick 完成。
- - Verified result / 验证结果:
工作负载 200、200、200：平均响应 1.00，平均周转 599.00，平均等待 399.00（见 data/q3_rr_200.txt）。
工作负载 100、200、300：平均响应 1.00，平均周转 465.67，平均等待 265.67（见 data/q3_rr_100_200_300.txt）。
- Analysis / 分析:
预测正确。RR 的平均响应时间只有 1，比 FIFO/SJF 的 200 和 133.33 好得多，因为每个任务在前几个 tick 内就能第一次运行。但平均周转时间明显变差：200、200、200 时 FIFO 是 400，RR 是 599，因为 RR 让所有任务交替推进，大家都拖到接近最后才完成。这说明 RR 优化响应时间，但牺牲周转时间。

## Q4: SJF 什么时候与 FIFO 的周转时间相同？
- Answer / 答案:
当任务按从短到长（长度不递减）的顺序到达时，SJF 与 FIFO 的周转时间相同。任务长度全部相同时也相同（Q1）。
- Reasoning / 理由:
SJF 总是先运行最短的任务。如果 FIFO 的到达顺序本来就是从短到长，两者的执行顺序一模一样，所以所有指标都一样（Q2）。如果长任务排在前面，FIFO 会让短任务等很久（护航效应），而 SJF 会把短任务提前，平均周转时间更低。

## Q5: SJF 什么时候与 RR 的响应时间相同？
- Answer / 答案:
当任务按从短到长排列，且除最后一个（最长的）任务外，每个任务的长度都小于等于时间片长度时，SJF 与 RR 的响应时间相同。
- Reasoning / 理由:
一个任务的响应时间取决于它前面的任务在它第一次运行前占用了多少时间。SJF 中是前面任务的完整长度之和；RR 中是前面任务各自的 min(时间片, 任务长度) 之和。两者相等，要求前面的任务都在一个时间片内完成，即长度 ≤ 时间片。

## Q6: SJF 中任务长度增加，响应时间怎么变？
- Answer / 答案:
响应时间随任务长度增加而增大，而且是线性增大。
- Reasoning / 理由:
SJF 中一个任务的响应时间等于它前面所有任务的长度之和。任务长度整体放大 k 倍，响应时间也放大 k 倍。例如 100、200、300 的平均响应时间是 133.33，长度翻倍为 200、400、600 时平均响应时间变成 266.67。
-- Verified result / 验证结果:
作业长度按 100、200、300 放大后，SJF 的平均响应时间如下（见 data/q6_sjf_base.txt、q6_sjf_double.txt、q6_sjf_triple.txt、q6_sjf_quad.txt）：

| 作业长度 | 平均响应时间 | 平均周转时间 |
|---|---|---|
| 100, 200, 300 | 133.33 | 333.33 |
| 200, 400, 600 | 266.67 | 666.67 |
| 300, 600, 900 | 400.00 | 1000.00 |
| 400, 800, 1200 | 533.33 | 1333.33 |

- Analysis / 分析:
预测正确。作业长度放大 k 倍，平均响应时间也放大 k 倍（133.33、266.67、400.00、533.33 每次增加 133.33），是线性增长。原因是 SJF 中一个作业的响应时间等于它前面所有作业的长度之和，长度整体变长，后面的作业等待更久。平均周转时间同样线性增长。

## Q7: RR 中时间片增大，响应时间怎么变？最坏响应时间公式？
- Answer / 答案:
时间片增大时，响应时间变大。N 个任务、时间片 q 时，最坏响应时间是 (N − 1) × q（前提是每个任务的长度至少为 q）。
- Reasoning / 理由:
最后一个任务要等前面 N − 1 个任务各跑完一个时间片才第一次运行，所以响应时间是 (N − 1) × q。以三个长度 100 的任务为例：q = 1 时最坏响应 2，q = 10 时最坏响应 20，q = 50 时最坏响应 100，q = 100 时最坏响应 200（此时 RR 变得和 FIFO 一样）。时间片越大，RR 的行为越接近 FIFO，响应时间越差，但上下文切换次数更少。
-- Verified result / 验证结果:
三个长度为 100 的作业，时间片取不同值时（见 data/q7_rr_q1.txt、q7_rr_q10.txt、q7_rr_q50.txt、q7_rr_q100.txt）：

| 时间片 q | 平均响应时间 | 平均周转时间 | 平均等待时间 |
|---|---|---|---|
| 1 | 1.00 | 299.00 | 199.00 |
| 10 | 10.00 | 290.00 | 190.00 |
| 50 | 50.00 | 250.00 | 150.00 |
| 100 | 100.00 | 200.00 | 100.00 |

- Analysis / 分析:
预测正确。平均响应时间等于 q（1、10、50、100）。三个作业的响应时间依次是 0、q、2q，平均是 q，最后一个作业的最坏响应时间是 2q，也就是 (N − 1) × q（N = 3），与我的公式一致。时间片增大，响应时间变差。q = 100 时每个作业在一个时间片内就跑完，RR 的行为与 FIFO 相同（平均周转 200，与 FIFO 相同）。另外还能看到：时间片增大时平均周转时间反而变好（299 → 200），因为作业不再被频繁打断。所以时间片越小，响应时间越好但周转时间越差，时间片越大则相反。
